# Старт работы над игрой

Это не веб-приложение: базы нет, серверной логики нет. Есть Go-обёртка, которая
отдаёт статику, и вся игра — файлы в `static/game/`. Игры пиксель-арт,
канва 360×640.

## 1. Прочитай перед первой правкой (именно в этом порядке)

1. `docs/brief.md` — бриф и концепт. **Нет файла или пустые разделы** → идёт
   фаза Бриф → Концепт: заполняй по шаблону файла, поля «целевая эмоция»,
   «почему игрок вернётся», «что делает игру честной» оставляй человеку.
   Код НЕ пишем, пока в брифе не стоит «Статус: концепт утверждён».
2. `static/game/config.js` — `window.ZV_GAME`: `title`, `archetype`, `brand`,
   `assets`. Показывает, какой кит выбран, цвета бренда и есть ли картинки.
3. `static/game/kits/<archetype>/README.md` — карта параметров твоего кита.
   Читай README до `kit.js`.
4. Скилл `archetype-<имя своего архетипа>` и скилл `game-runtime`.

Скиллы чужих архетипов не читай — это лишний контекст. Дальше по надобности:
`assets` (перед картинками), `mobile-contour`, `embed`, `ready-checklist`.
`static/vendor/` не читай никогда — это движок.

## 2. Как проверить, что не сломал

```sh
go build ./... && go test ./...
```
Тесты ловят то, что не видно на глаз: битые ссылки, внешние адреса, синтаксис
всех `static/**/*.js`, валидность `config.js` и известный `archetype`, ответы
обёртки, упоминания платформы. Красный тест — чини сразу: превью соберётся из
сломанного кода и человек увидит белый экран.

Живая проверка:
```sh
go run ./cmd/server >/tmp/game.log 2>&1 &
curl -sf localhost:8080/ >/dev/null && echo ok
```
Открой `/`, посмотри лог, погаси процесс. Ошибки JS так не поймать — после
каждой заметной правки сохраняй код и зови смотреть превью (есть QR «на
телефоне»).

## 3. Порядок работы

Прототип **на заглушках** — киты рисуют фигуры сами, картинки не нужны. Баланс
крутим на фигурах: это ходы, а не кредиты. Картинки заказываем один раз, когда
игра уже интересна (скилл `assets`). Каждая заметная правка: собрал → тесты →
сохранил → позвал смотреть превью.

## 4. Чего НЕ делать

- **Не трогай `static/vendor/`** — движок лежит локальной копией нужной версии
  (лицензия в `LICENSE-phaser`). Не обновляй, не минифицируй, не переименовывай.
- **Никаких CDN и внешних скриптов/шрифтов/стилей.** Всё, что грузит страница,
  либо лежит в репозитории, либо это URL картинки из файлов проекта. Игра
  встраивается на сайт бренда, сторонние запросы там недопустимы.
- **Не упоминай платформу и вендоров** — ни в `title`, ни в мета-тегах, ни в
  видимом тексте, ни в комментариях и `console.log`. Есть grep-тест, но не
  доводи до него.
- **Не добавляй Go-зависимости и не заводи второй `package main`** в корне:
  сборщик функции требует ровно один. Логика игры — только JS.
- **Не переизобретай мобильный контур** (портрет, масштаб, звук по первому
  тапу, экраны) — он в `shell.js`, скилл `mobile-contour`.
- **Не ломай пиксель-арт**: дробный `setScale`, свои твины масштаба и
  `add.text` вместо `ZV.ui.text` — скилл `game-runtime`.
- **Не генерируй картинки, пока концепт не утверждён** — это деньги человека.
- Не пиши в `docs/brief.md` за человека поля, помеченные как его.

## 5. Язык с человеком

Он продюсер игры, не программист. Не говори «сцена Phaser», «физическая
группа», «спрайт-лист», «коммит». Говори: «экран», «персонаж», «набор кадров»,
«сохранил». Спрашивай только продуктовое: приз, длина партии, что собираем,
чего избегаем. Технические решения принимай сам.
