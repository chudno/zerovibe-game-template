# Сюжет с мини-играми: узел `play`

Отдельного кита «гибрид» нет: это тот же `novel` или `quest`, где один узел
не реплика, а «сыграй». Сюжет останавливается, поднимается кит мини-игры,
её счёт и победа решают, куда пойдёт история дальше.

Файлы: сюжет — `content/novel.json` (или `content/quest.json`), сцена и ход
сюжета — `game/kits/novel/kit.js` и `game/kits/quest/kit.js`, разбор узла и
проверка графа — `game/novel.js`. Формат самого сюжета (узлы, варианты,
переменные, концовки) — скилл `archetype-novel`, здесь только про мини-игры.

Готовый пример целиком: `tests/fixtures/hybrid.json`.

## Что настроить под концепт

1. **Где остановить историю.** Мини-игра ставится там, где герой ЧТО-ТО
   делает: бежит, ищет, запоминает, успевает. Реплика перед узлом —
   подводка («Двери закрываются. Хватай пакеты»).
2. **Какой кит.** Имя из списка: `runner`, `catch`, `quiz`, `persona`,
   `wheel`, `platformer`, `memory`, `clicker`, `sort`. Сюжетные киты
   (`novel`, `quest`) внутрь не ставятся.
3. **Насколько короче.** `params` узла урезают партию вдвое против
   самостоятельного кита: `duration: 6000` вместо 20000, `pairs: 4` вместо
   6. Мини-игра обязана быть короче любой сцены вокруг неё.
4. **Куда лечь счёту.** Числовая переменная в `vars` — её потом можно
   спрашивать в условиях дальше по сюжету.
5. **Что видит игрок перед стартом.** `startLabel` (подпись кнопки) и
   `rules` (одна фраза, что делать).
6. **Куда ведут исходы.** `outcomes` — ветки сверху вниз, первая
   подошедшая выигрывает; последняя обязана быть без `if`.

Если игра брендированная (скилл `branding`) — приз в `config.prize`.

## Формат узла

```json
"lift_puzzle": {
  "bg": "lift",
  "speaker": "Курьер",
  "text": "Двери закрываются. Хватай пакеты, пока их не смело потоком людей.",
  "play": {
    "kit": "catch",
    "params": { "duration": 6000, "passScore": 3 },
    "score": "run_score",
    "startLabel": "Ловить",
    "rules": "Лови пакеты, пропускай мусор",
    "outcomes": [
      { "if": { "won": true }, "goto": "lift_fast", "add": { "hurry": 1 } },
      { "goto": "stairs" }
    ]
  }
}
```

| Поле | Что это |
|---|---|
| `kit` | имя кита мини-игры из списка выше |
| `params` | перекрытие параметров кита только на эту партию |
| `score` | имя числовой переменной из `vars`, куда лечь счёту |
| `startLabel` | подпись кнопки запуска (по умолчанию «Начать») |
| `rules` | одна фраза под кнопкой — что делать в мини-игре |
| `outcomes` | 1–4 ветки: `if` (плюс служебные `won` и `score`), `goto`, `set`, `add` |

Узел с `play` — четвёртый вид выхода: `choices`, `goto`, `end` или `play`,
ровно один из них.

## Что видит игрок

1. Реплика печатается как обычно — история предупреждает, что сейчас будет
   игра.
2. Вместо «дальше» — кнопка `startLabel` и серая строка `rules` под ней.
   Тап по панели мимо кнопки партию НЕ начинает: игрок должен решить сам.
3. Мини-игра идёт на весь экран, сюжет ждёт.
4. Партия кончилась — 0,9 секунды крупная строка итога поверх мини-игры,
   и только потом сюжет. Экран результата игры при этом не показывается:
   он бывает один раз за партию, в самом конце истории.
5. **Проигрыш — это ветка, а не конец.** Игрок потерял вариант, а не
   пятнадцать минут чтения. Ветка проигрыша обязана вести дальше по сюжету,
   а не в тупик.

## Правила, которые нельзя нарушать

- **Не больше трёх узлов `play` на сюжет.** Больше — и это уже не сюжет,
  а сборник мини-игр с подписями. Проверяется граф-чеком.
- **Последняя мини-игра обязана вести к РАЗНЫМ концовкам.** Иначе она
  украшение: сыграл, а история та же. Ставка растёт — первая мини-игра
  меняет реплику, последняя открывает концовку.
- **Порог ставится около середины.** Если в мини-игре максимум 6 очков,
  условие `{ "score": 6 }` означает «только идеальная игра» — это ловушка.
  Бери 3.
- **Мини-игра внутри мини-игры невозможна.** Один уровень вложенности,
  оболочка бросит исключение.
- **Партия мини-игры короче сцены вокруг неё.** См. `params` выше.

## Как читать ошибки граф-чека

Проверка идёт при загрузке игры и в `node --test`; каждая ошибка говорит,
что чинить в данных.

| Сообщение | Что делать |
|---|---|
| `play.kit: «novel» нельзя запускать из сюжета — доступны: …` | взять кит из перечисленных: сюжет внутрь сюжета не ставится |
| `play.score: переменная «X» не объявлена в vars` | добавить `"X": 0` в `vars` |
| `play.score: переменная «X» должна быть числом` | счёт — число, а не булево |
| `play: последняя ветка outcomes обязана быть без `if`…` | дописать в конец `{ "goto": "…" }`: после мини-игры всегда есть куда идти |
| `play.outcomes[i]: эта ветка недостижима — предыдущая ветка срабатывает всегда` | у ветки выше условие шире; если сравниваешь счёт — пиши порог явно: `score: {gte: N}` |
| `play: ни один исход не ведёт к концовке` | `goto` веток указывают на несуществующие узлы |
| `nodes: мини-игр в сюжете N, а можно не больше 3` | убрать лишние узлы `play` |
| `nodes.X: ровно одно из choices, goto, end, play` | у узла с `play` не должно быть ещё и `goto`/`choices` |

Отдельная грабля: если ветка после мини-игры объявлена недостижимой, а
по-человечески она достижима — значит, порог по счёту нигде не написан
числом. Обход подставляет только те значения счёта, которые встретились в
условиях; напиши `{ "score": { "gte": 3 } }`, и обе ветки станут видны.

## Готово, когда

- `node --test tests game` зелёный: граф-чек пропускает сюжет.
- В галерее (`tests/gallery.html`, карточка «Гибрид») история доходит до
  каждой концовки: и с выигранной мини-игрой, и с проигранной.
- Проигрыш мини-игры ведёт к другой концовке, а не в тупик и не в конец
  партии.
- Мини-игра занимает меньше времени, чем чтение вокруг неё.
- Кнопка запуска подписана по делу, под ней одна фраза правил, и по тапу
  мимо кнопки ничего не начинается.
