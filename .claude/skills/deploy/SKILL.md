# Публикация игры

Игра — статические файлы, публикация занимает секунды: платформа берёт
**сохранённый в git код** и выкладывает его новой версией (`v1`, `v2`, …).
По адресу игры открывается последняя версия; старые доступны по `/vN/`, и
человек может вернуть любую во вкладке «Встраивание». Ничего собирать и
архивировать не нужно.

Говори с человеком продуктово: «публикую…», «готово, игра открывается по
ссылке …». Никаких «деплой», «CI», «бакет», «домен» — только результат.

## Шаг 0 — перед публикацией

1. Чек-лист готовности (скилл `ready-checklist`) пройден — не пройден → скажи,
   что осталось, и не публикуй.
2. Всё сохранено: `git status` чист, `git push` прошёл. Публикация берёт только
   сохранённое — несохранённые правки в версию не попадут.
3. `node --test tests game` зелёный.

## Шаг 1 — запрос публикации

Эндпоинт и ключ уже лежат в переменных окружения твоего процесса:
`ZV_AGENT_DEPLOY_URL` и `ZV_AGENT_CALLBACK_KEY` (заголовок `X-API-Key`).
Пусто — публикация из этого окружения недоступна (локальный прогон), скажи
человеку, что выложить сейчас нельзя.

Один вызов:

```sh
curl -sS -X POST "$ZV_AGENT_DEPLOY_URL" \
  -H "X-API-Key: $ZV_AGENT_CALLBACK_KEY" -H "Content-Type: application/json" \
  -d '{"subdomain": "<имя>"}'
```

`<имя>` — адрес игры: только `a-z`, `0-9`, дефис, 1–63 символа, уникально на
платформе. Предложи человеку 1–2 варианта из названия игры латиницей
(«koshka-kurier») через `ask_user` и подставь его ответ. При повторной
публикации имя НЕ спрашивай — бери прежнее (оно есть в `domain` ответа
статуса, шаг 2).

Ответ: `status` и `domain` (полный адрес игры — бери его ОТСЮДА, не
придумывай). `pending` — версия выкладывается, обычно 5–20 секунд.
`setup_url`/`setup_token` у игры не приходят — у неё нет сервера и админа.

## Шаг 2 — дождаться и отдать ссылку

```sh
curl -sS "$ZV_AGENT_DEPLOY_STATUS_URL" -H "X-API-Key: $ZV_AGENT_CALLBACK_KEY"
```

Ответ `{status, error, domain}`:
- `pending` / `building` — ещё выкладывается, подожди 5 секунд и спроси снова
  (до минуты);
- `running` — готово: проверь `https://<domain>/` (200) и дай человеку ссылку;
- `failed` — в `error` причина: занятое имя → предложи другое; пустой репозиторий
  → сначала сохрани код; иначе покажи причину своими словами.

Публикация запускалась только что и ещё идёт — платформа вернёт текущую как
есть, повторно не запускай.

## Чего не делать

- Не публиковать без слова человека, «чтобы посмотрел» — для этого есть превью.
- Не показывать человеку ключ, эндпоинты и тело запроса.
- Не звать `/dev/projects/...` и не искать ключ вайбкодера — из пода публикуют
  только через `ZV_AGENT_DEPLOY_URL`.
