# Устройство шаблона

```
handler.go, assets.go, cmd/server/  обёртка и локальный запуск (не трогаешь)
static/vendor/                      движок, локальная копия (НЕ трогаешь)
static/index.html                   <div id="game"> + подключение скриптов
static/game/style.css               стили вокруг канвы (image-rendering!)
static/game/config.js               window.ZV_GAME — настройка и картинки
static/game/shell.js                window.ZV: экраны, ui/sprite/juice/floor
static/game/main.js                 берёт кит по config.archetype
static/game/kits/<a>/               kit.js + README.md — механика архетипа
```

**Механику пишешь в `kits/<archetype>/kit.js`**, настройку заказа — в
`config.js`. `shell.js` и `index.html` трогай, только если задача правда про
оболочку (новый экран, новое событие наружу), и после — тесты.

## Пиксель-арт: правила, которые нельзя нарушать

Ассеты рисуются 1:1 под канву и ставятся масштабом 1.

1. **База 360×640.** Координаты целые, центр `(180, 320)`. Не бери
   `window.innerWidth` — только `ZV.WIDTH` / `ZV.HEIGHT`.
2. **Дробный `setScale` запрещён.** Только 1, 2, 3: дробный рвёт пиксельную
   сетку внутри спрайта, картинка «шумит» на движении.
3. **Squash/stretch — не твином масштаба.** Бери `ZV.juice.squash/stretch`:
   они подменяют кадр и двигают картинку на целые пиксели.
4. **Наклона нет.** Произвольный `setAngle` мылит; нужен поворот — кратный 90°.
5. **`tileSprite` — только на текстуре 64/128/256 по стороне** (степень
   двойки), иначе WebGL сглаживает её вопреки `pixelArt`. Не уверен —
   обычный `add.image` с целым масштабом.
6. **`tilePositionX/Y` — через `Math.floor`**, дробь копи в своём поле, иначе
   текстура ползёт на полпикселя и мерцает.
7. **Текст — только `ZV.ui.text` / `ui.title` / `ui.hint`**: там моноширинный
   шрифт, `resolution` под экран и целые координаты. Свой `add.text` даст мыло.
8. **Тени и пыль — спрайтами/частицами целых размеров** (`ZV.juice.shadow`,
   `ZV.juice.dust`), не растянутым овалом.
9. Мыло на финальном апскейле снимает `image-rendering: pixelated` в
   `style.css` — **не удаляй строку**, без неё остальные флаги зря.

## Контракт кита и оболочки

```js
global.ZV_KITS.runner = { createScenes: function (config) { return [new PlayScene()]; } };
```
`ZV.boot` ставит перед сценами кита меню, после — результат, задаёт канву
360×640, `Scale.FIT`, пиксельный рендер и arcade с нулевой гравитацией. Ключ
игровой сцены — **`zv-play`**, не переименовывай.

Кит НЕ рисует меню и результат. Конец раунда — один вызов, он же шлёт событие
наружу (скилл `embed`):
```js
global.ZV.finish(scene, { score: 12, won: true, meta: {}, text: "препятствий" });
```

Киту доступно: `WIDTH`/`HEIGHT`, `PRIMARY`/`SECONDARY`, `FONT`,
`ui.button/title/hint/backdrop/text`, `sprite.apply/playAnim`,
`juice.squash/stretch/shadow/dust`, `floor`, `FLOOR_DEPTH`. Новый кит — добавь
`<script>` в `index.html`, иначе `ZV_KITS` его не увидит.

## config.js

`title`, `archetype` (runner|catch|quiz), `brand` (name/primary/secondary/
logoUrl) и `assets` (`hero` с frameWidth/frameHeight/frames/fps, `items`,
`background` с `tile`). Поля расписаны комментариями в самом файле. Пустой
`assets` — киты играют на заглушках, это рабочее состояние; как заказывать
картинки и что класть в поля — скилл `assets`. `embed` не трогай.

## Подстановка картинки: только через ZV.sprite.apply

Киты читают `config.assets` сами. Меняешь текстуру в коде — **только** так:
```js
ZV.sprite.apply(this.hero, { anim: "run", scale: 1 });
```
`setTexture()` и `play()` внутри зовут `setSizeToFrame()`: сбрасывают тело под
размер кадра и обнуляют offset. Тело из `create` после подстановки пропадает —
герой повисает над полом или проваливается. Хелпер помнит тело, ставит якорь
по низу ног и переприменяет тело при смене кадра.

- **Прозрачные поля кадра.** Пиксель-арт почти всегда приходит с пустотой по
  краям: у листа 96×96 ноги на y≈88, под ними ещё 8 прозрачных пикселей. Тело
  по размеру КАДРА встаёт ниже ног — герой висит над землёй. `apply` сам
  сканирует первый кадр и берёт **непрозрачную область**; числа в конфиге не
  нужны. Перебить — `bodyW`/`bodyH`/`offsetY` в `config.assets.hero` (нужно,
  только если хочется хитбокс уже силуэта). Картинка с чужого домена без CORS
  не сканируется — там задавай тело руками.
- `bodyW`/`bodyH` — в единицах ТЕКСТУРЫ, масштаб Arcade учитывает сам.
- `origin: false` — объекту нужен центр, а не низ (падающие предметы).
- Анимация на лету: `ZV.sprite.playAnim(obj, "jump")`; скорость — через
  `anims.timeScale`, **анимацию не пересоздавай**.
- Пол — `ZV.floor(scene, x, yTop, width, 14)`: тело уходит вниз на
  `FLOOR_DEPTH` (200 px), иначе быстрое тело пробивает его при просадке
  кадров. `fixedStep` (шаг 1/60) не выключай.
- **Не двигай ради «сока» ни `obj.y`, ни `displayOriginY`.** Координата у тела
  на полу дерётся с коллайдером. А `displayOriginY` физика читает напрямую:
  `body.position.y = obj.y + (body.offset.y − displayOriginY)`. Сдвиг картинки
  на 2 px поднимает тело над полом, `blocked.down` гаснет, герой падает
  обратно, кит видит «приземление» и снова дёргает «сок» — получается вечная
  дрожь вверх-вниз. Только `ZV.juice.squash`/`stretch`: они двигают картинку и
  компенсируют `body.offset.y`, тело остаётся на месте.
- **«Приземление» лови по факту отрыва**, а не по `blocked.down`: этот признак
  мигает на стыке кадров. Кит ставит флаг в момент прыжка и гасит его один раз
  при касании земли.
- Грузи только в `preload`, ошибку лови (`load.on("loaderror", …)`) и оставляй
  заглушку; ключ текстуры уникален на всю игру.

## Лимиты

- **Страница ≤ ~2 МБ** (пиксель-арт лёгкий: герой 64, предмет 32, фон 180×320).
- **Ни одного внешнего запроса**, кроме картинок из файлов проекта: движок
  локально, шрифты системные, никакой аналитики и `fetch` на чужие домены.
- Звук короткий, музыку на всю партию не тащи (вес + автоплей iOS).
- Прохождение не зависит от `localStorage`: iOS его чистит.
- Go-зависимости не добавляй, второй `package main` в корне не заводи.

## Проверка

`go build ./... && go test ./...` ловит битую ссылку, синтаксис JS, неизвестный
архетип и упоминания платформы. Затем `go run ./cmd/server`, открыть `/`,
проверить консоль — и сохранить код для превью на телефоне.
