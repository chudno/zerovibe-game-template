# Устройство шаблона

```
handler.go, assets.go    обёртка функции: отдаёт static/ (не трогаешь)
cmd/server/main.go       локальный запуск :8080 (не трогаешь)
static/index.html        страница: <div id="game">, подключает vendor + game/*
static/vendor/           движок, локальная копия (НЕ трогаешь)
static/game/style.css    стили страницы вокруг канвы (фон, отступы, тач)
static/game/config.js    window.ZV_GAME — вся настройка проекта
static/game/shell.js     window.ZV: экраны Играть→Игра→Результат, звук, события
static/game/main.js      точка входа: берёт кит из ZV_KITS по config.archetype
static/game/kits/<a>/    kit.js + README.md — механика архетипа
static/assets/           заглушки; настоящие картинки — по URL файлов проекта
docs/brief.md            бриф и концепт
```

Правило разделения: **механику пишешь в `kits/<archetype>/kit.js`**, настройку
заказа — в `config.js`. `shell.js` и `index.html` трогай, только если задача
правда про оболочку (новый экран, новое событие наружу), и после — тесты.

## Контракт кита и оболочки

`kit.js` в конце регистрирует себя:
```js
global.ZV_KITS.runner = { createScenes: function (config) { return [new PlayScene()]; } };
```
Оболочка (`ZV.boot`) ставит перед сценами кита экран меню, после — экран
результата, задаёт канву 720×1280, `Scale.FIT`, arcade-физику с нулевой
гравитацией. Ключ игровой сцены — **`zv-play`**: по нему оболочка и родительская
страница запускают раунд, не переименовывай.

Кит НЕ рисует меню и результат. Конец раунда — один вызов:
```js
global.ZV.finish(scene, { score: 12, won: true, meta: {}, text: "препятствий" });
```
`text` — подпись под числом на экране результата. Только этот вызов даёт экран
результата и событие `finish` наружу (скилл `embed`).

Доступное киту из `ZV`: `WIDTH`/`HEIGHT` (720/1280), `PRIMARY`/`SECONDARY`
(цвета бренда), `ui.button/title/hint/backdrop`, `sprite.apply/playAnim`,
`juice.squash/stretch/shadow/dust`, `floor` и `FLOOR_DEPTH`.

Все три `kit.js` подключены в `index.html` заранее, а `main.js` берёт нужный по
`archetype`. Заводишь новый кит — добавь `<script>` в `index.html` (иначе
`ZV_KITS` его не увидит) и файл README рядом.

## config.js

```js
window.ZV_GAME = {
  title: "Название игры",     // видит игрок; имени платформы тут нет
  archetype: "runner",         // runner | catch | quiz
  brand: {
    name: "Бренд",
    primary: "#4f7cff",        // акцент: кнопки, счёт
    secondary: "#ffd23f",      // второй акцент: цели, награды
    logoUrl: ""                // ссылка на файл проекта или пусто
  },
  embed: /* вычисляется из ?embed=1, не трогай */
};
```
Менять можно всё, кроме имён `ZV_GAME` и `embed`. `archetype` — только из
существующих китов, иначе красный тест и «Неизвестный архетип» на экране.
Цвета из брифа; держи контраст с тёмным фоном оболочки.

## Как подставить картинку

Настоящие ассеты в репозиторий НЕ кладём: они лежат в файлах проекта и имеют
постоянный URL. Грузим в `preload`, ставим — **только через `ZV.sprite.apply`**:

```js
PlayScene.prototype.preload = function () {
  this.load.spritesheet("hero", "https://<ссылка>/hero.png",
    { frameWidth: 96, frameHeight: 128 }); // размеры кадра — из ответа генерации
};

// в create или где меняешь картинку:
ZV.sprite.apply(this.hero, { anim: "run", bodyW: 72, bodyH: 120 });
```

Зачем хелпер: `setTexture()` и `anims.play()` внутри зовут `setSizeToFrame()`,
то есть сбрасывают тело под размер нового кадра и обнуляют offset. Тело,
заданное один раз в `create`, после подстановки спрайта пропадает — герой
повисает над полом или проваливается. `ZV.sprite.apply` запоминает нужное тело
на объекте и переприменяет его после каждой смены кадра (подписан на события
анимации), а якорь ставит по низу ног (`origin 0.5, 1`), чтобы точка опоры
осталась на земле при картинке другого размера.

- `bodyW`/`bodyH` — в единицах ТЕКСТУРЫ; масштаб Arcade учитывает сам,
  сплющивание из `ZV.juice` хитбокс не меняет.
- `origin: false` — если объекту нужен центр, а не низ (падающие предметы).
- Смена анимации на лету: `ZV.sprite.playAnim(obj, "jump")`.
- Пол делай через `ZV.floor(scene, x, yTop, width, 28)`: видимая полоска
  тонкая, а тело уходит вниз на `ZV.FLOOR_DEPTH` (400 px). Тонкий пол при
  просадке кадров пробивается быстрым телом насквозь.
- Физика игры идёт фиксированным шагом 1/60 (`fixedStep` в конфиге оболочки);
  не выключай — на нём держится вся защита от «проваливания».

«Сок» из `ZV.juice`: `squash` / `stretch` (сплющивание на приземлении и
растяжение в прыжке), `shadow` (овал под ногами, зови `zvFollow()` в `update`),
`dust` (пылинки). Всё на штатных твинах и частицах.

Грабли загрузки:
- Грузи только в `preload` — в `create` текстуры ещё нет.
- Ошибку лови: `this.load.on("loaderror", …)` → оставь фигуру-заглушку, иначе
  игрок увидит пустой экран.
- Ключ текстуры уникален на всю игру; одинаковые ключи в разных сценах —
  типичная причина «спрайт не тот».

## Лимиты

- **Страница целиком ≤ ~2 МБ**: спрайты 512 px, фон максимум 1024, PNG.
  Игру открывают с телефона по QR, часто на мобильном интернете.
- **Ни одного внешнего запроса**, кроме картинок из файлов проекта: движок
  локально, шрифты системные (`system-ui, sans-serif`), никакой аналитики и
  `fetch` на чужие домены.
- Звук — короткие файлы, музыку на всю партию не тащи (вес + автоплей на iOS).
- Никаких зависимостей от `localStorage` для прохождения: iOS его чистит.
- Один `<canvas>`, DOM внутри игры нет — указка по элементам не работает,
  правки от человека приходят словами.
- Go-зависимости не добавляй, второй `package main` в корне не заводи.

## Проверка после правки

`go build ./... && go test ./...` — тесты ловят битую ссылку, синтаксис JS,
неизвестный архетип и упоминания платформы. Затем `go run ./cmd/server`,
открыть `/`, проверить консоль браузера — и сохранить код, чтобы человек увидел
свежее превью на телефоне.

## Зависимости
НЕ добавляй Go-зависимости в go.mod: любая с директивой go 1.24+ ломает сборку функции (плагин под другой тулчейн, игра отвечает 502). Игре Go-библиотеки не нужны — вся логика в JS.
