# Устройство шаблона

```
handler.go              обёртка функции: отдаёт static/ (не трогаешь)
cmd/server/main.go      локальный запуск :8080 (не трогаешь)
static/index.html       страница: <div id="game">, подключает vendor + game/*
static/vendor/          движок, локальная копия (НЕ трогаешь)
static/game/config.js   window.ZV_GAME — вся настройка проекта
static/game/shell.js    экраны Играть→Игра→Результат, звук, события родителю
static/game/main.js     точка входа: берёт кит по config.archetype
static/game/kits/<a>/   kit.js + README.md — механика архетипа
static/assets/          ТОЛЬКО серые заглушки; настоящие картинки — по URL
docs/brief.md           бриф и концепт
```

Правило разделения: **механику пишешь в `kits/<archetype>/kit.js`**, настройку —
в `config.js`. `shell.js` и `index.html` трогай только если задача правда про
оболочку (новый экран, новое событие наружу), и после — прогони тесты.

## Контракт кита

`kit.js` экспортирует `createScenes(config)` и возвращает массив сцен движка;
оболочка сама их регистрирует, запускает и показывает экран результата.
Кит НЕ создаёт игру целиком, НЕ читает `window` напрямую (всё нужное приходит
в `config`) и НЕ рисует кнопки «Играть»/«Ещё раз» — это оболочка.

Конец раунда кит сообщает оболочке одним вызовом (см. README кита; обычно
`this.game.events.emit("zv:finish", {score, won, meta})`). Только так игрок
увидит экран результата и наружу уйдёт событие `finish` (скилл `embed`).

## config.js

```js
window.ZV_GAME = {
  title: "Курьер бежит",          // видит игрок; имени платформы тут нет
  archetype: "runner",             // runner | catch | quiz — какой кит взять
  brand: {
    name: "Бренд",
    colors: { primary: "#E4002B", bg: "#101014", accent: "#FFD400" },
    logoUrl: "",                   // URL файла проекта или пусто
  },
};
```
Менять можно всё, кроме имени переменной. `archetype` — только из известных
китов, иначе тест красный. Цвета бренда берутся из брифа; фон и текст держи
контрастными (мелкий текст на телефоне читается плохо).

## Как подставить картинку

Настоящие ассеты в репозиторий НЕ кладём — они лежат в файлах проекта и имеют
постоянный URL. Загрузка в ките:

```js
preload() {
  this.load.image("hero", CFG.assets.hero);           // прямой URL файла проекта
  this.load.spritesheet("run", CFG.assets.run, {
    frameWidth: 128, frameHeight: 128,                // из ответа генерации
  });
}
```
URL складывай в `config.js` (`assets: { hero: "https://…/hero.png" }`) — тогда
замена картинки не трогает код. Пока картинки нет — оставь заглушку из
`static/assets/`, игра должна собираться и играться на серых фигурах.

Грабли загрузки:
- Ошибку загрузки лови и не молчи: `this.load.on("loaderror", …)` → рисуй
  заглушку, иначе игрок получит пустой экран без объяснений.
- Не грузи картинку в `create()` — только `preload()` (или явный
  `this.load.start()`), иначе текстуры не будет к моменту отрисовки.
- Ключ текстуры уникален на всю игру; одинаковые ключи в разных сценах —
  типичная причина «спрайт не тот».

## Лимиты

- **Страница целиком ≤ ~2 МБ**, картинки — 512px, PNG; фон 1024 максимум.
  Игру открывают с телефона по QR, часто на мобильном интернете.
- **Ни одного внешнего запроса**, кроме картинок из файлов проекта: движок
  локально, шрифты системные (`system-ui, -apple-system, sans-serif`), никакой
  аналитики, никаких `fetch` на чужие домены.
- Звук — короткие файлы; без музыки на всю партию (вес + автоплей на iOS).
- Никаких `localStorage`-зависимостей для прохождения: iOS чистит хранилище,
  игра должна нормально работать «с чистого листа» при каждом открытии.
- Один `<canvas>`, DOM внутри игры нет: указка по элементам не работает,
  правки от человека приходят словами.

## Проверка после правки

`go build ./... && go test ./...` — тесты ловят битую ссылку, синтаксис JS,
неизвестный архетип и упоминания платформы. Потом `go run ./cmd/server`,
открыть `/`, проверить, что нет ошибок в консоли — и сохранить код, чтобы
человек увидел свежее превью на телефоне.
