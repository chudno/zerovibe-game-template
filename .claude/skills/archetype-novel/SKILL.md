# Новелла (novel): доводка кита

Файл `game/kits/novel/kit.js`, сюжет — `content/novel.json`. Реплика на
фоне с портретом, 2–4 варианта или «дальше», переменные открывают
реплики, несколько концовок с исходом. Кейс бренда: «день с продуктом»,
подбор товара через историю, обучение сотрудников, интерактивная реклама.

Пиксель-арт, `ZV.sprite.apply`, картинки — скилл `game-runtime`; здесь
только про сюжет.

## Что настроить под бриф

1. **Сюжет** — `content/novel.json` (формат — README кита): 8–20 узлов,
   2–3 концовки, одна–две переменные. Больше 40 узлов на промо не нужно:
   партия 1–3 минуты.
2. **Концовки** — у каждой `outcome` (для аналитики бренда), `title`,
   `text`, `won`; приз за концовку — `end.prize`, иначе при `won` —
   `config.prize`. Проигрышная концовка тоже нужна: выбор без цены не выбор.
3. **Главы** — `chapters`: 2–4 узла-начала глав, по ним партнёр видит
   воронку (событие `progress`).
4. **Картинки** — `config.assets.backgrounds` и `portraits` по ключам из
   узлов (скилл `assets`: фон `background` 180×320, портрет `sprite` с
   эмоцией как отдельный ключ). Пока картинок нет — цветные заглушки с
   подписью, сюжет уже играется.
5. **Темп** — `typeMs` (22): быстрее для коротких реплик, 0 — без печати.

## Как писать сюжет

- Один узел — одна мысль: до 5 строк по ~39 знаков (панель 312 px, кегль
  1). Валидатор считает по метрикам шрифта и скажет, где не влезло.
- Вариант — глагол и 2–5 слов («Бегу сразу», «Проверю адрес»); до 2 строк
  в кнопке. Варианты различимы по смыслу, не «да/нет/может быть».
- Переменные — для памяти о выборе: `add` копит (`hurry`), `set` ставит
  флаг (`careful`). Условие `if` открывает реплику только тем, кто
  «заслужил»; такая реплика обязана быть достижима — граф-чек это проверит.
- Линейные узлы (`goto`) — для ритма: реплика, ещё реплика, потом выбор.
  Не больше 2–3 линейных подряд, иначе игрок тапает не читая.
- Каждая ветка ведёт к концовке. Петли («вернуться в начало») граф-чек
  разрешает, если из петли есть выход; ловушку без выхода — нет.

После каждой правки:
```sh
node --test tests game
```
Ошибки графа читаются словами: «недостижим от start», «ловушка», «условие
никогда не выполняется», «концовок меньше двух».

## Грабли этой механики

- **Текст поверх текста** — реплики и варианты перезаполняются в
  существующих объектах (`setText`, `ui.choices.set`), новые не создаются.
  Свои надписи добавляй один раз в `create`.
- **Печать по буквам ломает переносы** — строки считаются заранее
  `ZV.font.wrap` и печатаются с готовыми `\n`; не печатай «сырой» текст.
- **Двойной тап** — во время печати тап показывает реплику целиком, а не
  идёт дальше; варианты появляются только после печати. Не снимай эту
  блокировку.
- **Свой `Math.random` для «случайной концовки»** — только `ZV.random`, и
  только если бриф этого просит; обычно исход должен зависеть от выбора.
- **Одноразовый промокод в концовке** — нельзя, страница публичная: общий
  оффер в `prize`, одноразовые коды выдаёт сайт по событию `finish`.
- Про `ZV.ui.choices`, `ZV.finish` с `outcome`, экран результата — `game-runtime`.

## Бренд

Фон — место действия бренда, портреты — маскот и клиент, реплики — тон
бренда, без лозунгов. `PRIMARY` подсвечивает выбранный вариант,
`SECONDARY` — имя говорящего. Логотип — на «Играть» и «Результат».

## Готово, когда

Все концовки достижимы (граф-чек), каждая прочитана тобой с телефона,
реплики влезают без ужатия, у победной концовки есть приз, у проигрышной —
понятно, где ошибся. Дальше — `ready-checklist`.
