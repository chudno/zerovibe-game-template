# Квест (quest): доводка кита

Файл `game/kits/quest/kit.js`, сюжет — `content/quest.json`. Всё как в
новелле (скилл `archetype-novel`: реплики, варианты, концовки, главы) плюс
предметы: полка иконок сверху, тост «Получено: …» / «Использовано: …»,
варианты, открытые только с предметом в руках. Кейс бренда: «собери набор —
получи скидку», квест по разделам сайта, «собери документы» для банка,
приключение с маскотом.

Сцена общая с новеллой (`game/stage.js`), граф общий (`game/novel.js`);
здесь только про предметы.

## Что настроить под бриф

1. **Предметы** — 3–6 штук в `items` (потолок 8: полка): `title` коротко
   (одна строка), `icon` — ключ картинки из `config.assets.items`; без
   картинки — цветная ячейка с буквой, играется и так.
2. **Сюжет вокруг «найди — примени»**: каждый предмет выдаётся (`give`) на
   одной ветке и нужен (`needs`) дальше; хотя бы один тратится (`take`) —
   так игрок чувствует цену. Ветка без предмета обязана вести куда-то
   (пусть в худшую концовку), а не в тупик.
3. **Концовки** — победная требует всех ключевых предметов (`needs` на
   последнем выборе), проигрышные — обходные пути. `won` и `outcome` у
   каждой; приз — `end.prize` или `config.prize`.
4. **Главы** — `chapters` по этапам поиска; `progress` уносит и `meta.items`.
5. **`showEmptySlots`** — пустые ячейки показывают, сколько ещё искать;
   выключай, если предметы — сюрприз.

## Как строить сюжет с предметами

- Предмет — булев флаг: `give` ставит, `take` снимает, `needs` проверяет
  все перечисленные. Обычные `vars`/`if` работают рядом (счётчик монет —
  `add`, «получил больше двух» — `if {coins: 2}`).
- Не давай предмет и требование в одном узле: `give` срабатывает при ВХОДЕ в
  узел, `needs` смотрит на варианты этого же узла — сработает, но игрок не
  поймёт, откуда предмет. Выдавай на шаг раньше, с репликой.
- Один и тот же предмет можно выдавать на разных ветках (пропуск через
  стойку или через звонок) — так у игрока всегда есть путь.
- Скрытый вариант игрок не видит совсем: оставь в узле хотя бы один
  вариант без `needs`, иначе при пустых руках кнопок не будет. Граф-чек это
  ловит: «при каком-то наборе предметов … не показывается ни один вариант».
- `needs` — только на варианте; на узле ворот нет, валидатор откажет.

После каждой правки:
```sh
node --test tests game
```
Ошибки читаются словами: «предмет нигде не выдаётся», «предмета … нет в
items», «предмет для этого варианта нельзя получить раньше», дальше — ошибки
графа новеллы.

## Грабли этой механики

- **Полка перерисовывается на каждый узел** (`drawShelf` в `show`), тост —
  по разнице инвентаря `rt.lastChange`; не считай предметы сам.
- **Иконки крупнее 28 px** ставятся масштабом 1/2, 1/3 (ровное
  прореживание) — рисуй иконки 28×28 или 56×56, иначе часть пикселей выпадет
  неровно.
- **`take` без `needs`** — снимает предмет, которого может не быть; это не
  ошибка, но сюжетно странно: обычно `take` идёт вместе с `needs`.
- **Одноразовый промокод в концовке** — нельзя, страница публичная.
- Остальное — `archetype-novel` и `game-runtime`.

## Готово, когда

Все концовки достижимы (граф-чек), победная проходится тобой с телефона с
полным набором предметов, тосты читаются, у проигрышных концовок понятно,
какого предмета не хватило. Дальше — `ready-checklist`.
