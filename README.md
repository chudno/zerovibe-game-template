# Шаблон HTML-игры 2D

Заготовка мобильной игры-одностраничника: портретная канва 360×640, пиксельный
рендер, движок Phaser локальной копией, одиннадцать готовых архетипов на
заглушках: раннер, ловилка, викторина, тест «какой ты», розыгрыш (колесо /
скретч / коробка), платформер с уровнями, новелла с выбором, квест с
инвентарём. Игра запускается и проходится сразу после клонирования — дальше
меняются настройки, тексты, уровни, сюжет и картинки, а не код.

Это **статические файлы**: ни сервера, ни сборки. Платформа кладёт их в бакет
и раздаёт по адресу игры; превью обновляется через несколько секунд после
`git push`, публикация создаёт версию (`v1`, `v2`, …) — по адресу игры
открывается последняя, любая доступна по `/vN/`.

## Запуск

```sh
python3 -m http.server 8080     # или любой статический сервер; http://localhost:8080
node --test tests game          # проверки шаблона (см. ниже)
```

## С чего начать

1. `game/config.js` — название, `archetype` (`runner` | `catch` | `quiz` |
   `persona` | `wheel` | `platformer` | `novel` | `quest` | `clicker` |
   `match3`), цвета игры
   (`theme`), `params`, секция `assets`.
2. `game/kits/<archetype>/README.md` — параметры кита (ключи `params` с
   дефолтами) и формат его файла в `content/`.
3. Тексты — в `content/<archetype>.json`; картинки — по ссылкам в
   `config.assets`, а не в репозитории (см. ниже).

## Параметры, контент, сид

- **Баланс** — `config.params`: `{ speedMax: 380, passScore: 12 }`. Ключи и
  дефолты — в README кита; неизвестный ключ даёт предупреждение в консоли и
  игру на дефолте. Код кита править не нужно.
- **Контент** — `content/<kit>.json`. Формат проверяется тестом и при старте
  игры: битый файл показывает список ошибок на экране, а не белую страницу.
- **Уровни** платформера — текстовые карты в `content/levels.json` (`#`
  земля, `o` монета, `^` шипы, `S` старт, `X` выход). Проходимость каждой
  карты считает солвер (`game/levels.js`): он повторяет физику движка тик в
  тик и ищет путь до выхода с запасом на взлёт; недостижимый выход или монета —
  ошибка данных. Ориентиры: прыжок ≈ 3,4 клетки вверх и ≈ 3,7 в длину.
- **Сюжет** новеллы — граф в `content/novel.json`: узел = реплика (фон,
  портрет, говорящий, текст) с 2–4 вариантами, «дальше» или концовкой;
  переменные с `set`/`add` и условиями `if` на вариантах; `chapters` для
  события `progress`. Граф-чек (`game/novel.js`) обходит состояния (узел ×
  переменные): каждый узел и не меньше двух концовок достижимы, ловушек без
  выхода нет, условная реплика где-то показана. Формат — README кита.
- **Квест** — та же новелла плюс `items`: предметы выдаются `give`,
  тратятся `take`, открывают варианты `needs` (внутри — булевы переменные);
  полка предметов сверху, тост при получении. Граф-чек добавляет: каждый
  предмет где-то выдаётся, нужный предмет можно получить раньше.
- **Тема** — `config.theme` `{ name, primary, secondary, logoUrl }`: подпись
  над названием, два акцента и необязательный логотип: оболочка рисует его
  целым масштабом на «Играть» (вместо подписи, до 240×80) и мелко на
  «Результат» (до 160×48); битая ссылка игру не ломает.
- **Приз** (необязательный слой) — если игра брендированная (скилл
  `branding`), приз кладётся в `config.prize`
  `{ title, code, text, button, url }`: при победе экран результата
  показывает карточку с кодом и кнопкой «Скопировать код» (или «Забрать» →
  `url`). У розыгрыша и «какой ты» приз живёт в их `content/*.json` и
  появляется только у брендированной игры — по умолчанию его нет. Без этой
  секции игра просто заканчивается результатом.
- **Сид** — `?seed=42` в адресе повторяет партию один в один: так
  воспроизводят жалобу («на третьем препятствии…») и так работает автопрогон.
  Внутри игры случайность только через `ZV.random`.

## Как заменить заглушки на картинки

Код кита править не нужно: киты читают `config.assets` сами, а пока там пусто —
рисуют фигуры и всё равно играются.

```js
assets: {
  hero: { url: "<ссылка>", frameWidth: 96, frameHeight: 96, frames: 8, fps: 10 },
  items: { block: { url: "<ссылка>" } },   // ключи — в README кита
  background: { url: "<ссылка>", tile: false }
}
```

- `frameWidth`/`frameHeight`/`frames` берутся из ответа генерации, не на глаз;
  кадров анимации будет не больше, чем реально есть в листе;
- файлы картинок в репозиторий не кладём — они живут в файлах проекта;
- `tile: true` только если обе стороны фона 64/128/256 (степень двойки), иначе
  WebGL сглаживает текстуру вопреки пиксельному режиму;
- фон любого размера подгоняется под канву (`game/layout.js`): кратно крупнее —
  ровное прореживание, мельче — целый апскейл, иначе cover;
- ошибка загрузки не ломает игру: кит остаётся на заглушке.

## Пиксель-арт

Игры пиксельные, и это накладывает жёсткие правила:

- канва 360×640, картинки рисуются 1:1 и ставятся масштабом 1;
- **дробный `setScale` запрещён** — он рвёт пиксельную сетку внутри спрайта;
  сплющивание и растяжение делает `ZV.juice` подменой кадра и сдвигом на целые
  пиксели, а не твином масштаба;
- `tileSprite` — только на текстуре со стороной 64/128/256;
- текст — через `ZV.ui.text` пиксельным шрифтом из атласа (см. «Шрифт»),
  кегль только целый множитель: `size: 1` (капитель 10 px), 2, 3, 4;
- `image-rendering: pixelated` в `style.css` — без этой строки финальный
  CSS-апскейл размоет идеальные пиксели, остальные флаги не помогут.

## Шрифт

Текст рисуется **спрайтами из атласа** (`BitmapText`), а не canvas-текстом
браузера: тот даже на точном кегле оставляет серые полупиксели по краям
глифов, требует ждать загрузки шрифта и по-разному выглядит на iOS, Android и
Windows. Атлас строится при старте из `game/fontdata.js` — растра шрифта
**Pixel Cyr** (Swamp Design & Dubina Nikolay, 2002): капитель 10 px, строка
16 px, строчные буквы — те же капители (шрифт без нижнего регистра).

- Кегль — `size: k` в стиле `ZV.ui.text`: 10·k px. Дробных кеглей нет;
  `fontSize: "24px"` по старой привычке округляется к ближайшему целому.
- Жирного нет: синтетический жирный размазал бы пиксели. Акцент — цветом и
  кеглем.
- Символов без глифа (`…`, `₽`, `№`, `€`, `$`, `°`) в шрифте нет — оболочка
  заменяет их (`...`, `р.`, `N`…), валидатор контента ругается на остальное.
- «Влезает ли текст» считается настоящими метриками (`game/font.js`):
  заголовок, кнопки, варианты ответов сами ужимаются с кегля 2 до 1, а
  валидатор `content/*.json` сообщает, сколько строк и знаков допустимо.
- Данные шрифта генерируются из TTF: `node tests/fontgen.js` (источник —
  `tests/fixtures/fonts/`, в публикацию не попадает). Тест следит, что
  `fontdata.js` соответствует файлу. Другой пиксельный шрифт — положить TTF,
  перегенерировать; генератор понимает прямоугольные контуры без составных
  глифов.

Лицензия Pixel Cyr: в файле стоит «All rights reserved», текста лицензии у
авторов нет; в каталоге соавтора (проект «ВЕДИ», 2002) шрифт помечен
«Бесплатно». Использование в публичных играх — решение владельца платформы;
запасной вариант с явной лицензией OFL — Tiny5 или Press Start 2P.

## Мобильный контур

Задан в `shell.js` и `style.css`, переизобретать не нужно: дизайн-канва
360×640 портрет, `Scale.FIT` + `CENTER_BOTH` + `autoRound`, тап по `pointerup`,
разблокировка звука первым касанием на экране «Играть», тач-цели от 24
логических px (≈48 css), `touch-action: none`, `viewport-fit=cover`.

## Встраивание на сайт

```html
<iframe src="https://<хост>/?embed=1" title="Игра" allow="autoplay; fullscreen"
  style="width:100%;max-width:420px;aspect-ratio:9/16;border:0;border-radius:16px"></iframe>
```

`?embed=1` прячет кнопку «Во весь экран». Закреплённая версия —
`https://<хост>/v3/?embed=1`: она не меняется при следующих публикациях.
Игра шлёт родителю:

```js
{ source: "zv-game", type: "ready" }                     // страница загрузилась
{ source: "zv-game", type: "start" }                     // игрок начал раунд
{ source: "zv-game", type: "progress", step, total, meta } // пройден уровень / началась глава
{ source: "zv-game", type: "finish", score, won, meta,   // раунд кончился;
  outcome?, prize?: { id, title, code } }                // исход словом и приз, если были
{ source: "zv-game", type: "prize", action, code, url? } // нажата кнопка карточки приза
{ source: "zv-game", type: "error", message, details }   // битый content/*.json
```

Обратно родитель может попросить перезапуск:

```js
iframe.contentWindow.postMessage({ source: "zv-host", type: "restart" }, "*");
```

## Что проверяют тесты

`node --test tests game` не даёт выложить сломанную игру:

- каждая ссылка в html/css/js указывает на существующий файл, внешних адресов
  в статике нет, в корне есть `index.html`;
- весь код игры парсится (синтаксическая ошибка в ките ловится до публикации);
- `config.js` указывает на существующий кит;
- геометрия китов (`game/layout.js`) — на размерах настоящих сгенерированных
  картинок из `tests/fixtures`: подгонка фона, сетка кадров, число кадров
  анимации, анимация по факту полёта, хитбокс;
- контракт картинок на тех же фикстурах: лист героя делится на кадры, у кадров
  прозрачные поля, ноги на одной высоте, у предметов снят хромакей;
- контракт кита (`tests/kits.test.js`): регистрация в `ZV_KITS` с `defaults`,
  README на каждый параметр, только `ZV.random`, только `ZV.sprite.apply`,
  без дробного масштаба, ключ сцены `zv-play`, `ZV.finish` на выходе;
- содержимое `content/*.json`: текст влезает в свою область по метрикам
  шрифта, индексы, веса, достижимость каждого типа, форма призов;
- баланс раннера (`game/balance.test.js`): время реакции ≥ 250 мс и окно
  прыжка ≥ 150 мс на всём диапазоне скоростей, пауза спавна ≥ 1,35 полёта;
- уровни платформера (`game/levels.test.js`): разбор карты, дальность прыжка,
  солвер на ручных и сгенерированных уровнях (яма 4 — да, 5 — нет; ступень
  3 — да, 4 — нет), непроходимые конструкции распознаются, план солвера
  исполняется симулятором до выхода;
- сюжет новеллы и квеста (`game/novel.test.js`): форма узлов и переменных,
  граф-чек (недостижимый узел, меньше двух концовок, ловушка, условие, которое
  никогда не выполняется), предметы (ссылки, выдача, недостижимый `needs`),
  инвентарь в рантайме, пути до каждой концовки;
- сид: одинаковая последовательность при одном сиде, взвешенный выбор
  сходится к весам;
- шрифт: `game/fontdata.js` совпадает с растром TTF, покрытие русского
  алфавита и знаков, ширины и переносы как у `BitmapText`;
- сетка, лента шагов, сейв и пул (`game/{grid,timeline,save,pool}.test.js`):
  раскладка целыми числами и пары ровно по два на 200 сидах; догон
  просроченных шагов и исключение в шаге без блокировки ввода; бросающее,
  битое и пустое хранилище не ломают партию; веса, антиповтор и `spread`;
<!-- week4 -->
- сюжет с мини-играми (`game/novel.test.js`, узел `play`): кит из белого
  списка, счёт в объявленную числовую переменную, последняя ветка без `if`,
  перекрытые ветки, потолок в три мини-игры, разбор исхода без `null`;
- раздача «памяти» (`game/memory.test.js`): чётность раскладки на 200 сидах,
  повторяемость по сиду, поле влезает в сетку тач-целей;
- экономика кликера (`game/clicker.test.js`): партия детерминирована, цель
  достижима при лучшей игре и НЕ достижима вчетверо более медленным тапом без
  покупок, кулдаун тапа держит потолок темпа, `needs` не блокирует очередь;
- темп «собери заказ» (`game/sort.test.js`): на любой скорости ленты предмет
  видно не меньше 350 мс и пауза между предметами длиннее его проезда — то же
  число валидатор проверяет по `config.params` и объясняет словами;
<!-- week5: match3 -->
- ядро «три в ряд» (`game/match3.test.js`): раздача без готовых троек и всегда
  с ходом на 200 сидах, совпадения с пересечениями, после каскада поле полное и
  без совпадений, перемешивание сохраняет состав фишек, лучшая игра набирает
  кратно больше случайных тычков — тем же прогоном валидатор сверяет
  `targetScore` с числом ходов;
- в статике нет имени платформы (игра живёт своей жизнью на чужом сайте), в
  корне нет `package.json`.

**Галерея китов** — `tests/gallery.html`: все архетипы на заглушках, каждый в
своём кадре 360×640 (на телефоне — по одному, с выбором), журнал событий
встраивания под кадром, «Заново», сид. Открыть локально:
`python3 -m http.server 8080` → `http://localhost:8080/tests/gallery.html`.
Игра одна на проект, переключателя архетипа в самой игре нет: галерея
собирает `index.html` с подменённым `config.js` (`srcdoc` + `<base>`).
Тест `tests/gallery.test.js` требует карточку на каждый кит.

**Headless-прогон** (`tests/e2e`, Playwright, отдельный job CI): игра в iframe
хоста с фиксированным сидом, бот-эксперт обязан выиграть, бот-новичок —
