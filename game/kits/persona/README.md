# Кит «Какой ты» (persona)

Тест без правильных ответов: каждый вариант даёт баллы одному или нескольким
типам, в конце побеждает тип с максимумом. Результат — «Ты — Спринтер» и
описание типа. Развлекательный формат «кто ты из …»: игрок узнаёт что-то про
себя и хочет показать результат друзьям; картинок не требует.

## Данные — `content/persona.json`

```json
{
  "types": [
    { "id": "sprinter", "title": "Спринтер", "text": "Скорость — твоё всё.",
      "prize": { "title": "Промокод на доставку", "code": "FAST15", "text": "…", "button": "Забрать", "url": "" } }
  ],
  "questions": [
    { "q": "Заказ горит. Что делаешь?",
      "answers": [
        { "text": "Срываюсь с места", "weights": { "sprinter": 2 } },
        { "text": "Смотрю карту", "weights": { "planner": 2 } }
      ] }
  ]
}
```

- типов от 2 до 8, `id` — латиница; `title` — до 2 строк заголовка «Ты — …»
  (кегль 2, ~18 знаков в строке), `text` — до 4 строк по ~36 знаков (кегль 1);
  вопросы и ответы — как у квиза (валидатор считает по метрикам шрифта);
- у каждого ответа `weights` — баллы типам (числа ≥ 0), хотя бы один > 0;
- каждый тип обязан получать баллы хотя бы за один ответ — иначе он не выпадет
  никогда (валидатор это ловит);
- при равенстве баллов побеждает тип, который стоит в файле раньше: порядок
  типов — это приоритет;
- `prize` у типа необязателен; без него экран результата — только портрет типа.

## Что крутить — `config.params`

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| `timePerQuestion` | 0 | секунд на вопрос; 0 — без таймера (тест не торопит) |
| `questionsPerRound` | 0 | сколько вопросов показать; 0 — все |
| `shuffleQuestions` | true | мешать порядок вопросов |
| `shuffleAnswers` | true | мешать варианты внутри вопроса |

## Что делает механику интересной

- Типы должны быть узнаваемыми: игрок хочет сказать «это про меня» — характеры,
  а не абстрактные категории.
- Вопросы про ситуации, а не про свойства: «заказ горит — что делаешь» читается
  живее, чем «ты быстрый?».
- Честность: любой тип достижим, и по ответам видно, к чему шло — иначе результат
  ощущается случайным.
- Темп: 6–10 вопросов, по 2–4 варианта. Длиннее — бросают на середине.
- «Ещё раз»: игрок перепроходит, чтобы получить другой тип, — описания типов
  должны быть настолько разными, чтобы ради них стоило вернуться.

## Что уходит наружу

`finish` несёт `outcome` — `id` победившего типа — и `prize` (если у типа он
есть). Счёта у теста нет, экран результата показывает заголовок, описание типа
и карточку приза.

Если игра брендированная (скилл `branding`) — приз задаётся в `config.prize`.
