# Кит «Бегун» (runner)

Герой бежит на месте, дорожка едет навстречу, тап — прыжок. Раунд кончается,
когда герой врезался; счёт — число пройденных препятствий.

## Что крутить

Объект `S` в начале `kit.js`:

| Поле | Что делает |
| --- | --- |
| `gravity` | притяжение; больше — падение резче, прыжок «злее» |
| `jump` | сила прыжка (высота) |
| `speedStart` / `speedMax` | скорость препятствий в начале и потолок |
| `speedStep` | прибавка скорости за каждое пройденное препятствие |
| `spawnStart` / `spawnMin` | пауза между препятствиями и её нижняя граница |
| `spawnStep` | на сколько пауза сокращается с каждым препятствием |
| `lives` | сколько столкновений переживает герой |

Порог победы (`won`) — в функции `finish`: сейчас 15 препятствий.
Верх дорожки — константа `GROUND_Y` (канва 360×640, портрет).

Числа связаны: при `jump` 850 и `gravity` 2600 полёт длится 0,65 с, высота
134 px. `spawnMin` (700 мс) обязан оставаться больше времени полёта — иначе на
максимальной сложности появляются непроходимые пары препятствий.

## Главное правило подстановки картинок

**После смены картинки герой обязан стоять на земле.** Любая смена текстуры
или анимации идёт только через `ZV.sprite.apply` — он один переприменяет тело
после `setTexture`/`play` (эти вызовы Phaser сбрасывают тело под размер кадра)
и держит якорь по низу ног (`origin 0.5, 1`), чтобы точка опоры не уезжала.

```js
ZV.sprite.apply(this.hero, {
  texture: "hero",   // или anim: "run"
  scale: 1           // только целое: дробный масштаб рвёт пиксели
  // bodyW/bodyH/offsetY не обязательны: см. «Прозрачные поля» ниже
});
```
Прямой `hero.setTexture(...)` или `hero.anims.play(...)` в обход хелпера —
это «герой висит в воздухе» или «проваливается»; так провалилась первая игра.
После правки проверь в консоли: `ZV.game.scene.getScene('zv-play').hero.body.blocked.down`
должно быть `true`, когда герой на земле.

## Прозрачные поля вокруг кадра

**Пиксель-арт почти всегда приходит с пустыми полями по краям кадра.** У листа
96×96 фигура занимает по вертикали примерно y 6–88, то есть под ногами ещё
8 прозрачных пикселей. Если считать тело по размеру КАДРА, его низ окажется
на 8 px ниже ног — герой повиснет над землёй или утонет в ней.

`ZV.sprite.apply` разбирается с этим сам: при первой подстановке он сканирует
первый кадр текстуры и берёт **непрозрачную область** — её ширину, высоту и
положение. Ноги встают на землю без единого числа в конфиге.

Перебить автообрезку можно через `config.assets.hero` — эти поля имеют
приоритет и нужны, только если хочется хитбокс уже силуэта:

```js
hero: { url: "…", frameWidth: 96, frameHeight: 96, frames: 8, fps: 10,
        bodyW: 40, bodyH: 79, offsetY: 9 }   // необязательно
```

Проверить, что автообрезка сработала:

```js
var h = ZV.game.scene.getScene('zv-play').hero;
h.body.width + 'x' + h.body.height   // тело по фигуре, а не 96×96
h.getData('zvFootPad')               // прозрачных пикселей под ногами
```

Оговорка: пиксели читаются через canvas, поэтому картинка с чужого домена без
CORS не сканируется (canvas «портится»). Тогда автообрезки не будет — задай
`bodyW`/`bodyH`/`offsetY` руками.

## Чего нельзя делать с телом на полу

**Нельзя менять `displayOriginY` у спрайта, у которого есть тело Arcade.**
Физика считает позицию тела как
`body.position.y = gameObject.y + (body.offset.y − displayOriginY)`,
то есть `displayOrigin` входит в неё напрямую. Сдвиг картинки на 2 px поднимал
тело на 2 px над полом, `blocked.down` гас, включалась гравитация, герой падал
обратно, кит видел «приземление» и снова дёргал «сок» — герой дрожал вверх-вниз
и уже не останавливался. Именно этот цикл сломал первую игру на шаблоне.

Правильно — `ZV.juice.squash`/`stretch`: они двигают картинку и **одновременно**
компенсируют `body.offset.y`, так что разность не меняется и тело стоит на месте.

И не переприменяй тело на каждом кадре анимации: `ZV.sprite.refresh` трогает
`setSize`/`setOffset`, только когда РАЗМЕР КАДРА действительно изменился.

## Ассеты

Картинки описываются в `config.assets`, код кита править не нужно. Пока там
пусто — рисуются заглушки, и игра всё равно проходится.

| Ключ в `config.assets` | Что это | Размер заглушки |
| --- | --- | --- |
| `hero` | герой, лист кадров бега | 32×50 на кадр |
| `items.block` | низкое препятствие | 32×32 |
| `items.blockTall` | высокое препятствие | 32×60 |
| `items.ground` | тайл дорожки | 32×32 |
| `background` | фон | нет |

```js
assets: {
  hero: { url: "<ссылка>", frameWidth: 64, frameHeight: 64, frames: 8, fps: 10 },
  items: { block: { url: "<ссылка>" }, blockTall: { url: "<ссылка>" } },
  background: { url: "<ссылка>", tile: false }
}
```

`frameWidth`/`frameHeight`/`frames` бери **из ответа генерации**, не угадывай:
`makeAnims` соберёт бег по `frames` сам, пересоздавать анимацию не нужно.
Тело героя после смены картинки править не надо — оно считается по непрозрачной
области кадра (см. «Прозрачные поля»); кит только сужает его по ширине до 70 %,
чтобы касание плечом не считалось столкновением.

Дорожка — `tileSprite` тайлом 32 px во всю ширину канвы независимо от размера
текстуры: сторона степень двойки, поэтому текстура не мылит. Если у фона своя
нарисованная дорога, кит приглушает полоску до alpha 0.35, а совсем убрать её
можно так:

```js
assets: { ground: { visible: false }, background: { url: "<ссылка>" } }
```

Фон подгоняется под канву 360×640 сам:

| Текстура | Что делает кит |
| --- | --- |
| `tile: true`, стороны 64/128/256 | `tileSprite`, бесшовный параллакс |
| кратно крупнее канвы (720×1280) | масштаб 1/n — ровное прореживание пикселей |
| кратно мельче (180×320) | целый апскейл ×n |
| произвольный размер | `cover`: заполняет канву, лишнее за краем |

Пока фон есть, кит не рисует заглушки неба и земли — они закрывали картинку.

Пол рисует оболочка (`ZV.floor`): видимую полоску даёт дорожка, а тело уходит
вниз на `ZV.FLOOR_DEPTH` (200 px) — иначе быстро падающий герой пролетает
сквозь него.

## Анимация и «сок»

Анимации `run` / `jump` / `idle` заведены в `makeAnims` — кит живой сразу.
Темп бега привязан к скорости мира в `updateAnim` через
`anims.timeScale = clamp(speed / speedStart, 0.6, 2)`: анимация НЕ
пересоздаётся, меняется только её скорость.

Оболочка даёт готовые приёмы (`ZV.juice`), кит их уже использует:
- `squash(scene, obj, frame, ms)` — просадка картинки на приземлении;
- `stretch(...)` — подъём на взлёте;
- `shadow(scene, obj, groundY, w)` — тень отдельным спрайтом, зови `zvFollow()`
  в `update`;
- `dust(scene, x, y, color)` — 3 пылинки на приземлении.

Это пиксель-арт, поэтому «сок» сделан **без дробного масштаба**: вместо твина
`scaleX/scaleY` — подмена кадра и сдвиг картинки на целые пиксели. Свои твины
по масштабу спрайта не пиши.

Сдвиг идёт по `displayOriginY`, а не по `obj.y`: сдвиг координаты у тела,
лежащего на полу, дерётся с коллайдером — герой зависает в воздухе и больше
не приземляется.

## Проверка

`go test ./...`, затем `go run ./cmd/server` и открыть `/`: герой стоит на
дорожке, ноги перебирают, прыжок с приземлением даёт сплющивание и пыль,
консоль без ошибок.
