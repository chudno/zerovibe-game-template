# Кит «Квест» (quest)

Новелла с инвентарём: реплики на фоне с портретом, варианты ответа, а
сверху — полка предметов. Предметы выдаются по ходу сюжета (`give`),
тратятся (`take`) и открывают варианты (`needs`): без пропуска в лифт не
пустят, ключ откроет склад. Концовок несколько, у каждой исход.

## Данные — `content/quest.json`

Формат новеллы (`game/kits/novel/README.md`) плюс `items` и три поля на
узлах и вариантах:

```json
{
  "start": "gate",
  "items": {
    "pass": { "title": "Пропуск", "icon": "pass" },
    "key":  { "title": "Ключ от склада", "icon": "key" }
  },
  "nodes": {
    "gate": { "text": "Охранник: «Без пропуска не пущу».",
      "choices": [
        { "text": "Оформить пропуск", "goto": "desk" },
        { "text": "Позвонить начальнику", "goto": "call" }
      ] },
    "desk": { "text": "Держите пропуск.", "give": ["pass"], "goto": "hall" },
    "call": { "text": "Ключ у охраны.", "give": ["key"], "goto": "hall" },
    "hall": { "text": "Куда?", "choices": [
        { "text": "На лифте в офис", "goto": "office", "needs": ["pass"] },
        { "text": "Открыть склад", "goto": "warehouse", "needs": ["key"], "take": ["key"] }
      ] }
  }
}
```

- `items` — от 1 до 8 предметов (больше не влезает в полку): ключ латиницей,
  `title` (одна строка до ~32 знаков, кегль 1 — в тосте и по тапу на полке),
  `icon` — ключ картинки из `config.assets.items` (без картинки — цветная
  ячейка с первой буквой).
- `give: [ключ…]` на узле (при входе) или варианте (при выборе) — предмет в
  инвентарь; `take` — из инвентаря; `needs` ТОЛЬКО на варианте — показывать
  его лишь с этими предметами в руках (у узла ворот нет, `needs` на узле —
  ошибка). Внутри это булевы переменные, так что обычные `vars`, `set`,
  `add`, `if` тоже работают рядом.
- Проверка: каждый предмет где-то выдаётся; `needs` выполним — есть путь,
  где предмет уже в руках (иначе «предмет для этого варианта нельзя получить
  раньше»); в узле всегда виден хотя бы один вариант (иначе «не показывается
  ни один вариант — оставь вариант без needs/if»); дальше весь граф-чек
  новеллы (достижимость, ≥2 концовок, ловушки). Слишком ветвистый сюжет
  (больше 60 000 состояний узел × переменные) валидатор не обходит и просит
  упростить.

## Что крутить — `config.params`

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| `typeMs` | 22 | мс на букву при печати реплики; 0 — показывать сразу |
| `tapReveals` | true | тап во время печати показывает реплику целиком |
| `autoNextMs` | 0 | линейный узел сам идёт дальше через столько мс; 0 — по тапу |
| `startNode` | "" | начать с этого узла (отладка ветки); пусто — `start` |
| `showEmptySlots` | true | рисовать пустые ячейки под ещё не найденные предметы (игрок видит, сколько искать) |

## Ассеты

| Ключ в `config.assets` | Что это | Размер |
| --- | --- | --- |
| `backgrounds.<ключ>` | фон узла | 180×320 или 360×640 |
| `portraits.<ключ>` | портрет говорящего | до 200×240 |
| `items.<ключ>` | иконка предмета (`items.<k>.icon`) | 28×28 (крупнее — масштаб 1/2, 1/3: рисуй 28 или 56) |

## Что уходит наружу

`progress` на главу (с `meta.items` — что в руках), `finish` с `outcome`
концовки, `won`, `meta.items` (инвентарь в конце), `meta.steps`. Приз — из
концовки (`end.prize`) или `config.prize` при `won`.

## Управление

Как в новелле: тап по панели — дальше / показать целиком, тап по варианту —
выбор, тап по предмету на полке — его название. На компьютере пробел/Enter
и клавиши 1–4.
