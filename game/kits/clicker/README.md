# Кит «Кликер» (clicker)

Тап по герою даёт очки, герой растёт по стадиям, апгрейды множат тап и дают
доход в секунду, шкала нужды падает сама и гасится кнопкой ухода. Партия
**всегда кончается**: по времени (`duration`) или когда набрана `goal.score` —
что раньше. Победа — цель набрана; иначе на экране результата «Стадия N: …»,
до которой дорос.

Три зоны, все достаёт палец одной руки: герой 160×160 по центру, кнопка ухода
72×72 внизу слева, карточки апгрейдов столбиком внизу справа.

## Данные — `content/clicker.json`

```json
{
  "goal": { "score": 400, "title": "Вырос!", "text": "Росток стал деревом" },
  "stages": [
    { "at": 0,   "title": "Семечко", "text": "Всё начинается с малого", "art": "stage1", "color": "#2e9e5b" },
    { "at": 120, "title": "Росток",  "text": "Первый лист развернулся", "art": "stage2", "color": "#38bdf8" },
    { "at": 380, "title": "Деревце", "text": "Ветки тянутся вверх",     "art": "stage3", "color": "#ffd23f" }
  ],
  "care": { "title": "Полить" },
  "upgrades": [
    { "id": "soil", "title": "Хорошая почва", "cost": 45,  "perTap": 1, "max": 3 },
    { "id": "sun",  "title": "Тёплый свет",   "cost": 120, "perSec": 3, "max": 2 },
    { "id": "rain", "title": "Тёплый дождь",  "cost": 200, "perTap": 3, "max": 2, "needs": "sun" }
  ]
}
```

| Поле | Что это |
| --- | --- |
| `goal.score` | сколько очков надо набрать; целое ≥ 10 |
| `goal.title` / `goal.text` | заголовок и строка на экране победы |
| `stages[].at` | с какого счёта показывается стадия; первая всегда `0`, дальше строго больше |
| `stages[].title` | название стадии (надпись при переходе и заголовок результата) |
| `stages[].text` | одна строка про стадию (необязательно) |
| `stages[].art` | ключ картинки героя в `config.assets.items` (необязательно) |
| `stages[].color` | цвет заглушки героя вида `#2e9e5b` (необязательно) |
| `care.title` | подпись кнопки ухода (влезает в 72 px: одно короткое слово) |
| `upgrades[].id` | латиница/цифры, уникален |
| `upgrades[].cost` | цена ПЕРВОЙ ступени; каждая следующая вдвое дороже |
| `upgrades[].perTap` / `perSec` | что даёт ступень: очки за тап и/или очки в секунду; хотя бы одно > 0 |
| `upgrades[].max` | сколько ступеней можно купить (1…99) |
| `upgrades[].needs` | `id` другого апгрейда: пока у того нет ни одной ступени, этот не показывается |

Стадий 1…6, апгрейдов 0…6. Последняя `stages[].at` обязана быть **меньше**
`goal.score` — иначе последняя стадия никогда не покажется.

**Достижимость цели проверяется автоматически** (`game/clicker.js`, тот же код
гоняет `node --test tests game` и кит при старте): солвер играет партию на
модельном времени шагом 100 мс тем же темпом, что и бот-эксперт
(`botTapsPerSec`), перебирая порядок покупок (при ≤ 6 апгрейдах — полный
перебор). Цель не набирается — ошибка данных со словами «при лучшей игре
выходит N». Обратный знак тоже ошибка: если цель набирается простыми тапами
вчетверо реже и без покупок, апгрейды и уход в игре лишние.

## Что крутить — `config.params`

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| `duration` | 75000 | длина партии, мс; 0 — только по цели |
| `tapPoints` | 1 | базовые очки за тап |
| `tapCooldownMs` | 30 | минимальный интервал между засчитанными тапами (защита от автокликера и дребезга) |
| `autoTickMs` | 1000 | как часто начисляется `perSec` |
| `startScore` | 0 | стартовые очки |
| `showUpgrades` | 3 | сколько карточек апгрейдов на экране сразу |
| `decayPerSec` | 6 | сколько нужды (из 100) уходит в секунду |
| `decayDelayMs` | 12000 | когда нужда НАЧИНАЕТ падать — первые 10 секунд без наказания |
| `decayRamp` | 1.8 | во сколько раз быстрее нужда падает к концу партии |
| `hungryFactor` | 0.5 | множитель очков при пустой шкале (ничего не отнимается, только замедляется) |
| `careCooldownMs` | 4000 | кулдаун кнопки ухода |
| `saveProgress` | true | помнить лучший счёт и число открытых стадий (`ZV.save`) |
| `botTapsPerSec` | 5 | темп «эталонного игрока»: им считает солвер и играет бот-эксперт |

Меняешь любой из них — меняется достижимость цели: прогони `node --test tests
game`, валидатор пересчитает экономику с новыми числами.

## Ассеты

| Ключ в `config.assets` | Что это | Размер |
| --- | --- | --- |
| `items.<stage.art>` | картинка героя на стадию (свой ключ на каждую) | до 160×160 |

Ключ берётся из `stages[].art`: `{ "at": 120, "art": "stage2" }` ищет
`config.assets.items.stage2`. Картинки нет — герой это квадрат 160×160 цвета
стадии с её номером по центру, и игра полностью играется как есть.

## Что уходит наружу

`progress` — на каждую стадию (`step` = номер стадии, `total` = сколько их
всего). `finish` — `score`, `won` (цель набрана), `title` вида
«Стадия 3: Деревце», `meta`: `archetype`, `stage`, `stages`, `taps`,
`upgrades` (сколько ступеней куплено), `careUses`, `seconds`, `record`.
Если игра брендированная (скилл `branding`) — приз за победу в `config.prize`.

## Сохранение

`ZV.save` хранит **только** лучший счёт и число открытых стадий. Партия
всегда начинается со `startScore` и с нуля апгрейдов, поэтому игра одинаково
проходится и в приватном окне, и при запрещённых куках.

## Что делает механику интересной

- **Тап должен спорить сам с собой.** Палец один, а дел три: набивать очки,
  гасить нужду, покупать. Как только все три конкурируют — «долби быстрее»
  перестаёт работать и начинается игра.
- **Первый апгрейд — момент «о!».** Игрок видит, что тап стал давать 4 вместо
  1, и понимает, что игра про экономику, а не про скорость пальца. Первый
  апгрейд должен окупаться секунд за 15, не дольше.
- **Стадии видно.** Смена стадии — это другой цвет, другая картинка, тряска и
  надпись. Если стадии похожи, рост не читается и партия ощущается ровной.
- **Первые 10 секунд без наказания.** Нужда начинает падать только на 12-й
  секунде: человек успевает понять правила до того, как с него спросят.
- **Проиграть нельзя, можно не дорасти.** Это мягкий конец: на результате
  видно, до какой стадии дошёл и какая была следующей.

## Почему у кликера есть конец

Бесконечный тамагочи на телефоне длится ровно до первого отвлечения и не даёт
ни победы, ни рассказа о себе. Партия на 75 секунд кончается фразой «дорос до
деревца», которую человек может кому-то сказать, — и ради которой запустит
игру второй раз.

## Для автопрогона

`window.__zvBot.clicker()` отдаёт состояние партии: `score`, `perTap`,
`perSec`, `stage`, `goal`, `need`, `careReady`, `upgrades` (`id`, `cost`,
`level`, `max`, `x`, `y`) и `over`. План покупок для бота-эксперта считает
`ZV.clicker.best(data, params)` — тот же солвер, что и валидатор. В обычной
игре ничего этого нет.
