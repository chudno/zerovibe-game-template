# Кит «Платформер» (platformer)

Герой ходит и прыгает по уровню из клеток, собирает монеты, обходит шипы и
доходит до двери — дальше следующий уровень. Управление: три кнопки внизу
экрана (влево, вправо, прыжок), на компьютере — стрелки/WASD и пробел.
Уровни — текстовые карты в `content/levels.json`; новый уровень = новая
карта, код не трогаем.

## Данные — `content/levels.json`

```json
{
  "levels": [
    { "name": "Разминка", "hint": "Дойди до двери",
      "map": [
        "....................",
        "..........o.........",
        ".S.......###......X.",
        "########....########"
      ] }
  ]
}
```

Символы карты (клетка 32×32, канва 360×640 = 11 клеток в ширину, 17 в высоту
над панелью кнопок):

| Символ | Что это |
| --- | --- |
| `#` | земля/стена (сплошная клетка) |
| `.` | пусто |
| `S` | старт героя (ровно один) — под ним нужна опора |
| `X` | выход (дверь), хотя бы один |
| `o` | монета |
| `^` | шипы — касание снимает жизнь и возвращает на старт уровня |

Правила формы: строки одной длины, от 8 до 200 столбцов, от 4 до 40 строк,
до 20 уровней. Уровень уже канвы дополняется камерой: она едет за героем.
Уровень ниже 17 строк прижимается к низу игрового поля.

**Проходимость проверяется автоматически** (`game/levels.js`, тот же код
гоняет `node --test tests game` и кит при старте): солвер повторяет физику
движка тик в тик и ищет путь от старта к выходу с запасом ±6 px на взлёт.
Выход недостижим или монета недостижима — это ошибка данных: экран ошибки
вместо уровня. Ориентиры при дефолтной физике: **прыжок ≈ 3,4 клетки вверх и
≈ 3,7 в длину**, герой 1,5 клетки ростом — проём высотой в одну клетку не
проходится, яма в 4 клетки перепрыгивается, в 5 — нет, ступень в 3 клетки
берётся, в 4 — нет. Платформа прямо над точкой взлёта мешает головой:
разноси платформы по горизонтали.

## Что крутить — `config.params`

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| `moveSpeed` | 170 | скорость бега, px/с |
| `gravity` | 1800 | притяжение, px/с² |
| `jump` | 640 | скорость прыжка; высота = jump²/(2·gravity) ≈ 114 px |
| `maxFall` | 900 | потолок скорости падения (не выше 900 — иначе тело пробивает пол) |
| `coyoteMs` | 80 | «время койота»: прыгнуть можно ещё столько мс после схода с края |
| `bufferMs` | 100 | буфер прыжка: нажатие за столько мс до приземления сработает |
| `lives` | 3 | жизней на раунд |
| `coinPoints` | 10 | очков за монету |
| `levelBonus` | 50 | очков за пройденный уровень |
| `levelsPerRound` | 0 | сколько уровней в раунде; 0 — все |
| `startLevel` | 1 | с какого уровня начинать (для отладки) |

Меняешь физику — солвер пересчитает проходимость с новыми числами (он берёт их
из `params`), но уровни могли стать непроходимыми: прогони `node --test`.

## Ассеты

| Ключ в `config.assets` | Что это | Размер |
| --- | --- | --- |
| `hero` | лист кадров героя (бег), тело всегда 22×48 по ногам | любой, тело обрежется |
| `items.ground` | тайл земли | 32×32 |
| `items.coin` | монета | 16×16 |
| `items.spike` | шипы | 32×32 (опасная зона — нижние 14 px) |
| `items.exit` | дверь | 32×32 |
| `background` | фон, едет за камерой | — |

Пусто — заглушки, игра проходится. Тело героя фиксировано (22×48): карта
рисуется под него, картинка может быть крупнее.

## Что уходит наружу

`progress` — на каждый пройденный уровень (`step`/`total`), `finish` —
`won`, если пройдены все уровни; `meta.levels` — сколько пройдено,
`meta.coins` — собрано монет. Приз за победу — `config.prize`.

## Для автопрогона

Сцена читает ввод из `scene.botPad = { dir, jump }`, если он задан
(`tests/e2e/bots.js`); план солвера исполняется `ZV.levels.follower`. В обычной
игре поля нет.
