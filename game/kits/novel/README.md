# Кит «Новелла» (novel)

Сюжет с выбором: реплика на фоне с портретом говорящего, 2–4 варианта
ответа или «дальше», переменные, которые открывают реплики, и несколько
концовок с исходом. Картинок не требует — играется на заглушках; фоны и
портреты подставляются по ключам.

## Данные — `content/novel.json`

```json
{
  "start": "intro",
  "vars": { "hurry": 0, "careful": false },
  "chapters": ["intro", "road", "meet"],
  "nodes": {
    "intro": {
      "bg": "office", "portrait": "hero", "speaker": "Курьер",
      "text": "Заказ горит. Что делаешь?",
      "choices": [
        { "text": "Бегу сразу", "goto": "road", "add": { "hurry": 1 } },
        { "text": "Проверю адрес", "goto": "check", "set": { "careful": true } }
      ]
    },
    "check": { "text": "Адрес верный.", "goto": "road" },
    "road":  { "text": "Куда?", "choices": [
        { "text": "Через парк", "goto": "good" },
        { "text": "Позвонить", "goto": "good", "if": { "careful": true } }
      ] },
    "good":  { "text": "Доставлено.", "end": { "outcome": "friend", "title": "Постоянный клиент", "won": true } }
  }
}
```

- `start` — id первого узла; `nodes` — от 2 до 300 узлов, id латиницей.
- Узел: `text` (до 5 строк по ~39 знаков, кегль 1), `speaker` (имя над
  репликой), `bg` и `portrait` — ключи картинок из `config.assets`
  (`backgrounds`, `portraits`); без картинки — цветная заглушка с подписью.
  Ровно один выход: `choices` (2–4 варианта), `goto` (линейно, по тапу
  «дальше») или `end`.
- Вариант: `text` (до 2 строк в кнопке), `goto`, необязательные `set`
  (`{имя: значение}`), `add` (`{имя: прибавка}`) и `if` — условие показа:
  `{имя: true}` для булевых, `{имя: 2}` значит «не меньше 2», или
  `{имя: {gte|lte|eq|gt|lt: n}}`. Скрытый вариант игрок не видит.
- `set`/`add` можно ставить и на узел — сработают при входе в него.
- `vars` — все переменные с начальными значениями; неизвестное имя —
  ошибка.
- `end`: `outcome` (исход для аналитики), `title` и `text` экрана
  результата, `won` (по умолчанию true), `prize` (необязательно: если игра
  брендированная — скилл branding — карточка приза за эту концовку; иначе
  при `won` берётся `config.prize`).
- `chapters` — id узлов, с которых начинаются главы: при входе игра шлёт
  событие `progress` (глава / всего).

**Граф проверяется автоматически** (`game/novel.js`, `node --test tests
game` и при старте игры) обходом по состояниям (узел × переменные): каждый
узел достижим от `start`, концовок не меньше двух, из любого состояния есть
путь к концовке (нет ловушек), у каждого условного варианта есть путь, на
котором он показан, все `goto` существуют, переменные объявлены. Ошибка —
экран со списком вместо игры.

## Что крутить — `config.params`

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| `typeMs` | 22 | мс на букву при печати реплики; 0 — показывать сразу |
| `tapReveals` | true | тап во время печати показывает реплику целиком |
| `autoNextMs` | 0 | линейный узел сам идёт дальше через столько мс; 0 — по тапу |
| `startNode` | "" | начать с этого узла (отладка ветки); пусто — `start` |

## Ассеты

| Ключ в `config.assets` | Что это | Размер |
| --- | --- | --- |
| `backgrounds.<ключ>` | фон узла (`node.bg`) | 180×320 или 360×640 |
| `portraits.<ключ>` | портрет говорящего (`node.portrait`) | до 200×240, ставится целым масштабом |

Эмоции — отдельные ключи: `hero`, `hero-angry`; в узле `"portrait":
"hero-angry"`. Ключи — латиница, цифры, `-`, `_`, `:`.

## Узел мини-игры (`play`)

Один узел может быть не репликой, а «сыграй»: сюжет останавливается,
поднимается другой кит, счёт партии открывает ветку. Формат, пороги и
правила — скилл `.claude/skills/archetype-hybrid/SKILL.md`, готовый
пример — `tests/fixtures/hybrid.json`.

```json
"lift_puzzle": {
  "text": "Двери закрываются. Хватай пакеты.",
  "play": {
    "kit": "catch",
    "params": { "duration": 6000, "passScore": 3 },
    "score": "run_score",
    "startLabel": "Ловить",
    "rules": "Лови пакеты, пропускай мусор",
    "outcomes": [
      { "if": { "won": true }, "goto": "lift_fast" },
      { "goto": "stairs" }
    ]
  }
}
```

`play` — четвёртый вид выхода наравне с `choices`, `goto` и `end`. Вместо
«дальше» рисуется кнопка `startLabel` со строкой `rules` под ней; после
партии 0,9 с показывается итог, и сюжет идёт по первой подошедшей ветке
`outcomes` (последняя обязана быть без `if`). Проигрыш — ветка, а не конец.
Не больше трёх таких узлов на сюжет; `novel` и `quest` внутрь не ставятся.

## Что уходит наружу

`progress` на каждую главу, `finish` с `outcome` = исход концовки,
`won` из концовки, `meta.ending`, `meta.steps` (сколько узлов пройдено),
`meta.vars`. Счёта нет — экран результата показывает заголовок и текст
концовки (и карточку приза, если она задана).

## Что делает механику интересной

- Выбор должен ощущаться выбором: варианты ведут к разному, а не сходятся
  через реплику в одно и то же.
- Темп: короткие реплики, развилка каждые 3–5 узлов; длинный линейный
  кусок без решений читается как стена текста.
- Честность: последствие видно игроку — переменная, которая открыла
  реплику, должна быть узнаваема («я же тогда проверил адрес»).
- Рост ставок: ближе к концу выборы дороже и отменить их нельзя.
- «Ещё раз»: концовок несколько, и после финала понятно, что была другая
  ветка — это и есть повод перепройти.

## Управление

Тап по панели — «дальше» (или показать реплику целиком), тап по варианту —
выбор. На компьютере: пробел/Enter и клавиши 1–4.
